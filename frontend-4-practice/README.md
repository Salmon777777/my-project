# Задание 4. Асинхронный JavaScript и создание React-приложений

Страница BORODA из задания 3 подключена к имитационному серверу курса. Текущая дата и слоты приходят двумя отдельными HTTP-запросами. Запасных локальных расписаний в клиенте нет.

## Запуск

Node.js 22.12+ или 24+.

```sh
npm ci
npm run dev
```

Откройте адрес Vite (обычно http://localhost:3000).

```sh
npm run lint
npm test
npm run build
```

API работает в `npm run dev`: серверный плагин курса оставлен без изменений. `npm run preview` показывает сборку, но для работы API нужен отдельный backend; для полной проверки используйте dev-сервер. Простое открытие HTML также не запускает приложение.

## API и данные

- `GET /api/booking/today` → `{year, month, day}`.
- `GET /api/slots?day=26&month=9&year=2026` → `{date, slots}`.
- Месяц начинается с 0. Серверная дата: 26 октября 2026.
- На чётных и нечётных днях различается доступность 11:00.
- Задержка ответа — 500 мс, как в шаблоне курса.
- Данные меняются только в `server/database.js`. Для демонстрации пустого дня можно задать одному из массивов слотов значение `[]`.

## Реализация

`src/api.js` отвечает за fetch, HTTP/сетевые ошибки, проверку JSON, отмену и таймаут 10 секунд. Хук `useAsyncResource` делает запросы в `useEffect`, хранит loading/error/data и даёт повторить запрос. При смене дня запрос отменяется; очистка эффекта также не даёт устаревшему ответу заменить актуальные данные. Дата из ответа проверяется.

Сначала загружается «сегодня», затем монтируется календарь и запрашиваются слоты. Каждый новый день запускает отдельный запрос. Во время загрузки или ошибки нельзя продолжить со старым временем. Сохранены сброс времени, навигация по месяцам/годам, запрет прошлых дат и оформление BORODA.

## Проверка

1. Откройте Network → Fetch/XHR: сначала today, затем slots, ответы 200 JSON.
2. Выберите 27 октября: сначала загрузка, затем новое расписание; 11:00 занято.
3. Выберите время, затем другую дату: выбранное время сброшено.
4. Быстро переключите дни: остаётся расписание последнего дня.
5. Остановите dev-сервер, оставив страницу открытой; выберите другой день: появится ошибка с повторной попыткой. Запустите сервер и повторите запрос.
6. Для начальной ошибки временно задайте некорректный `today` в серверной базе: появится ошибка вместо бесконечной загрузки. Восстановите данные и повторите запрос.

`npm test` проверяет успешные ответы, HTTP/сетевые ошибки, неверные данные и отмену. Реальная запись в барбершоп не отправляется.
