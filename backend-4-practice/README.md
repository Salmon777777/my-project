# Backend. Задание 4

Pydantic-модель `ServiceCreate` и `POST /services`, сохраняющий услугу через SQLAlchemy в SQLite.
Проект разделён на database, models, schemas и routers/services.

Ограничения:
- `categoryId`: положительный целочисленный ID существующей категории (неизвестная категория — 404).
- `title`, `desc`: после удаления пробелов по краям от 1 до 100 символов.
- `duration`: целое число минут от 30 до 180 включительно.
- `price`: положительное конечное число; до двух знаков после запятой, денежное значение хранится как Decimal/Numeric.
- Некорректное тело запроса даёт 422 до обращения к сохранению.

При первом запуске создаются четыре категории из практики 2 и два мастера из практики 3.
Сохранены GET-маршруты категорий и мастеров; `GET /services` позволяет проверить созданную услугу.
`servicesCount` вычисляется по реальным строкам БД. При создании услуги оно увеличивается.

Python 3.10+. Из этой папки:
```sh
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload
python -m pytest -q
```
Swagger: http://127.0.0.1:8000/docs
Пример POST /services:
```json
{"categoryId":3,"title":"Наращивание ресниц","desc":"Огромные ресницы уже через 30 минут","duration":30,"price":1500.00}
```
Ответ 201 содержит ID и поля созданной услуги; Decimal в JSON ответа представлен строкой для сохранения точности.
Для примеров с `price: "бесплатно"`, пустым `desc`, нулевой длительностью и отрицательной ценой возвращается 422.

База `salon.db` автоматически создаётся рядом с README и сохраняется после остановки.
18 проверок на временных БД: примеры из курса, пустые/длинные строки, границы длительности, неверные типы, нулевая и отрицательная цена, неизвестная категория, реальное сохранение, обновление счётчика и перезапуск.
